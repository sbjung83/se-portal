# SE Portal

서버 엔지니어 업무 관리 포털입니다. 사이트·장비, 점검 일정, 기술지원, 장애처리, 프로젝트, 주간보고서, 결재 문서, 기술 노트를 한곳에서 관리합니다.

- 웹 브라우저로 접속하는 사내 전용 서비스입니다. 별도 프로그램 설치는 필요 없습니다.
- 엔지니어마다 자기 계정으로 로그인하고, 각자 자기 데이터만 봅니다. 예외는 OS별 EOS 현황처럼 모두 같이 보는 자료입니다.

문서 구성:
- **1부 사용 안내**: 엔지니어(사용자)용
- **2부 운영 안내**: 관리자, 인수인계용
- **변경 이력**

> 코드 구조와 개발 규칙은 [CLAUDE.md](CLAUDE.md)에 있습니다.

# 1부. 사용 안내

## 시작하기

1. 브라우저에서 포털 주소(`https://<포털 서버 주소>`)로 접속합니다.
   - 사내 자체 인증서를 쓰기 때문에 처음 접속하면 "안전하지 않음" 경고가 나옵니다.
   - **고급 → 계속 진행**을 누르면 됩니다.
2. **회원 가입**을 누르고 다음 항목을 입력합니다.
   - 아이디, 비밀번호(8자 이상), 이름, 부서, 직급, 이메일
3. 관리자가 승인하면 로그인할 수 있습니다. 승인 전에는 "승인 대기" 안내가 나옵니다.
4. 로그인은 마지막으로 사용한 날부터 30일 동안 유지됩니다.
5. 비밀번호를 5번 연속 틀리면 5분 동안 로그인이 잠깁니다.

계정 메뉴(화면 오른쪽 위)에서 할 수 있는 일:
- **내 정보 수정**: 부서, 직급, 이메일 수정. 아이디와 이름은 바꿀 수 없습니다.
- **비밀번호 변경**: 변경하면 다른 곳에 로그인되어 있던 세션은 모두 끊깁니다.

## 메뉴별 기능

### 대시보드
이번 주 점검·기술지원 일정, 처리 중인 장애, 이달 실적(점검·기술지원·장애 건수), 진행 중인 프로젝트, 미처리 이슈, 보증 만료가 다가오는 장비를 요약해서 보여 줍니다. 화면을 열어 두면 자동으로 새로 고쳐집니다.

### 사이트
| 메뉴 | 설명 |
|---|---|
| **사이트 관리** | 고객사(사이트)와 장비 목록, 접속 정보, 점검표 파일, 특이사항, 이슈를 관리합니다. 목록에서 사이트마다 이번 달 점검 진행(완료/전체)과 확인할 것(이슈·체크리스트·워런티)을 보여 줍니다. 상세 창의 탭에는 건수가 붙고, 각 탭은 검색 칸과 추가 버튼이 있는 표이며 줄을 누르면 수정 창이 열립니다. 접속 비밀번호는 암호화되어 저장됩니다. |
| **사이트 체크리스트** | 사이트별 확인 항목을 관리합니다. 주기가 '월간'·'분기'인 항목은 다음 주기가 되면 자동으로 '미완료'로 돌아갑니다. 마감 칸에는 남은 날(D-n, 7일 이내 주황·3일 이내 빨강)만 표시하고 날짜는 위 요약 카드에 있습니다. 체크리스트가 없는 사이트는 맨 아래 접힌 상자에 모여 있습니다. |

### 프로젝트
**프로젝트 관리**: 프로젝트와 세부 작업(대기/진행중/완료)을 관리합니다.
- 기한이 지난 작업은 지연으로 표시됩니다.
- 완료보고서, 검수확인서, 구성도, 회의록 같은 제출자료를 첨부할 수 있습니다. 파일 하나당 50MB까지입니다.

### 서비스 지원
점검 일정, 기술지원, 장애처리는 **하나의 입력 창**에서 등록합니다. 세 목록은 같은 모양(날짜 / 사이트 / 제목 / 구분 / 작업자 / 상태 / 관리)이며, 요약 카드를 누르면 그 조건만, 줄을 누르면 수정 창이 열립니다.
- 창 위의 구분(점검 / 기술지원 / 장애처리 / 납품 / 유선원격 / 이전 / 기타)을 체크합니다. 여러 개를 함께 체크할 수 있습니다.
- '장애처리'를 체크하면 창 아래에 **장애처리 보고서** 탭이 생깁니다. 이때 상태 칸은 접수/처리중/완료 하나로 관리되고, 장애를 '완료'하면 함께 등록한 일정도 완료됩니다(목록에서 완료 체크를 해도 장애가 같이 완료).
- 체크한 구분에 따라 각 메뉴의 목록에 들어갑니다. 목록의 구분 칸에는 함께 체크한 구분이 그대로 보입니다(예: 기술지원 목록에 `기술지원` `장애처리`).
- 점검·기술지원·장애처리·서비스 지원 이력은 위의 '년도 월' 글자를 누르면 다른 해·달을 바로 고를 수 있습니다(크롬·엣지. 지원하지 않는 브라우저에서는 ◀ ▶ 버튼으로 이동).
- 다른 달에 끝내지 못한 건이 있으면 달 이동 버튼 옆에 '다른 달 지연 n건 →'이 나오고, 누르면 그 달로 갑니다.

| 메뉴 | 설명 |
|---|---|
| **점검** | 월간·분기·특별 점검 일정. 지난달 일정을 이번 달로 한꺼번에 복사할 수 있습니다. |
| **기술지원** | 작업계획서(MOP)를 작성하고 엑셀로 내려받습니다. |
| **장애처리** | 장애 접수부터 처리 완료까지 기록합니다. 보고서에 **사용 파트**(파트명·Part No.·수량·제거/장착 S/N·비고)를 줄 단위로 남길 수 있고, 파트명이나 S/N으로도 검색됩니다. 목록의 **Excel** 버튼이나 입력 창 위의 버튼으로 **장애처리 보고서**(한 장짜리 엑셀)를 내려받습니다. |
| **서비스 지원 이력** | 점검, 기술지원, 장애처리를 월 단위로 모아 봅니다. 검색어를 넣으면 그 해 전체에서 찾습니다. |
| **주간보고서** | 한 주(월~일)의 실적을 회사 주간보고서 엑셀 양식에 자동으로 채워 내려받습니다. 위의 '2026년 11월 3주차' 글자를 누르면 해·달을 고르고 그 달의 주차(주별 지원 건수 표시)를 눌러 지난 보고서로 바로 갑니다. 주차는 월요일 기준(그 주 월요일이 든 달)입니다. 확정사항에는 다음 주에 등록된 점검·기술지원·장애처리가 구분과 함께 자동으로 들어갑니다. |

### 결재 문서
**결재 문서 관리**: 문서 종류마다 탭이 있습니다. 입력한 내용은 회사 양식(엑셀/워드)에 채워져 내려받아집니다.

| 탭 | 설명 |
|---|---|
| **휴가원** | 종류, 기간, 사유를 입력하면 휴가원 양식을 만들어 줍니다. 연차 사용 내역과 남은 연차(연차·월차만 차감)를 함께 관리합니다. 일수는 평일 기준으로 자동 계산되며, **공휴일은 직접 빼야** 합니다. |
| **차량 운행 일지** | 월 단위로 씁니다. 처음 여는 달은 점검·기술지원 일정을 운행 기록으로 자동으로 가져옵니다. 출발·도착 km만 넣으면 그 사이 거리를 거래처별로 나눠 채워 주는 기능도 있습니다. 기본 정보(성명, 차종 등)는 한 번 넣으면 계속 쓰고, 언제든 고칠 수 있습니다. |
| **법인차량 점검 품의서** | 정비 내역(품목·단가·수량)을 입력하면 품의서를 만들어 줍니다. 저장한 정비 이력은 연도별로 볼 수 있습니다. |
| **개인 경비** | 월별 경비 내역(법인카드/현금)을 입력하면 정산 내역서를 만들어 줍니다. 카드 번호는 암호화해서 저장하며, 양식에는 끝 4자리만 들어갑니다. |

### 지식 창고

### 시스템
| 메뉴 | 설명 |
|---|---|
| **사내 테스트서버** | 테스트 서버의 접속 정보(계정·비밀번호)를 관리하고, 브라우저에서 바로 **SSH 터미널 / RDP 원격 데스크톱 / 웹 관리 화면**으로 접속합니다. 자세한 내용은 아래 참고. |

| **개발 체크리스트** | 관리자만 보입니다. 포털 개발 할 일 목록입니다. |

**사내 테스트서버 이용 시 알아 둘 점**
- 원격 접속은 **입력이 30분 동안 없으면** 자동으로 끊깁니다.
- 포털에서 로그아웃하거나, 비밀번호를 바꾸거나, 계정이 중지되면 1분 안에 끊깁니다.
- 접속과 **비밀번호 보기·복사는 모두 기록**됩니다. 관리자는 모든 엔지니어의 기록을 볼 수 있습니다.

# 2부. 운영 안내

## 구성

```
브라우저 ──HTTPS(443)──▶ nginx ──▶ uvicorn(127.0.0.1:8000, FastAPI) ──▶ SQLite (data/portal.db)
                                         │
                                         └─▶ guacd 컨테이너(127.0.0.1:4822) ── RDP 원격 접속용
```

| 항목 | 내용 |
|---|---|
| OS | Rocky Linux 9 |
| 실행 계정 | `appuser` (systemd 서비스 `se-portal`) |
| 설치 위치 | `/opt/se-portal` |
| 웹 서버 | nginx. 80은 443으로 넘기고, 443은 자체 서명 인증서(`/etc/pki/nginx/se-portal.crt`) 사용 |
| 앱 | Python 3.11, FastAPI, SQLAlchemy. 패키지는 `/opt/se-portal/venv` |
| RDP 변환 | guacd (podman 컨테이너, systemd 서비스 `guacd`) |
| 외부 접속 | 구글 캘린더(iCal), endoflife.date, learn.microsoft.com, esupport.ibm.com, www.ibm.com (EOS 갱신) |

## 새 서버에 설치

```bash
# 1. 소스 배치
git clone <저장소 주소> /opt/se-portal
cd /opt/se-portal

# 2. 설치 (python3.11, nginx, venv, systemd, SELinux, 방화벽, 인증서)
sudo bash install.sh

# 3. RDP 원격 접속을 쓸 경우 guacd 설치
sudo dnf install -y podman
sudo cp guacd.container /etc/containers/systemd/
sudo systemctl daemon-reload
sudo systemctl start guacd
```

설치 후 반드시 할 일:
1. **문서 양식 파일 넣기**. 양식 파일은 실명이 들어 있어서 git에 없습니다. 기존 서버나 백업에서 복사합니다.
   - `data/doc_templates/`: `leave.docx`, `car_log.xlsx`, `car_repair.xlsx`, `expense.xlsx`
   - `data/report_templates/`: `weekly_report.xlsx`
   - 복사한 뒤 `chown -R appuser:appuser data/`를 실행합니다.
2. **첫 계정 가입**. 계정이 하나도 없을 때 가입한 첫 사용자는 바로 승인되고 **관리자**가 됩니다.
3. **관리자 추가**. 다른 계정도 관리자로 만들려면 DB에서 직접 바꿉니다.
   ```bash
   sudo -u appuser /opt/se-portal/venv/bin/python -c \
     "import sqlite3;c=sqlite3.connect('/opt/se-portal/data/portal.db');c.execute(\"UPDATE users SET is_admin=1 WHERE username='아이디'\");c.commit()"
   ```

## 일상 운영

```bash
systemctl status se-portal          # 상태
sudo systemctl restart se-portal    # 재시작
journalctl -u se-portal -f          # 앱 로그
tail -f /var/log/nginx/error.log    # nginx 로그
systemctl status guacd              # RDP 변환 엔진
```

**재시작하기 전에 확인할 것**: 재시작하면 지금 열려 있는 SSH/RDP 원격 접속이 모두 끊깁니다. 원격 접속 중인 사람이 있는지 먼저 확인하세요. 아래 명령 결과에 '접속 중' 기록이 있으면 접속 중인 사람이 있는 것입니다.
```bash
sudo -u appuser /opt/se-portal/venv/bin/python -c \
  "import sqlite3;c=sqlite3.connect('/opt/se-portal/data/portal.db');print(c.execute(\"SELECT * FROM lab_access_logs WHERE result='접속 중'\").fetchall())"
```

**업데이트 반영 순서**
1. `git pull`
2. 새 패키지가 있으면 `venv/bin/pip install -r requirements.txt`
3. `sudo systemctl restart se-portal`

새 테이블은 시작할 때 자동으로 만들어집니다.

## 백업 (가장 중요)

| 대상 | 내용 | 비고 |
|---|---|---|
| `data/portal.db` | 모든 데이터 | |
| `data/secret.key` | 접속 비밀번호·카드 번호 암호화 키 | **이 파일을 잃으면 암호화된 값은 복구할 수 없습니다. DB와 반드시 함께 보관하세요.** |
| `uploads/` | 사이트 점검 보고서, 프로젝트 제출자료 | |
| `data/doc_templates/`, `data/report_templates/` | 문서 양식 | |

서비스를 멈추지 않고 DB를 백업하는 방법:
```bash
D=/백업위치/se-portal-$(date +%Y%m%d)
mkdir -p $D
sudo -u appuser /opt/se-portal/venv/bin/python -c \
  "import sqlite3;s=sqlite3.connect('/opt/se-portal/data/portal.db');d=sqlite3.connect('$D/portal.db');s.backup(d)"
cp -a /opt/se-portal/data/secret.key /opt/se-portal/data/doc_templates /opt/se-portal/data/report_templates /opt/se-portal/uploads $D/
```

**복원**: 서비스를 멈춘 뒤 위 파일들을 제자리에 돌려놓고, `chown -R appuser:appuser`로 소유자를 맞춘 다음 서비스를 시작합니다.

## 보안 설정 요약
- 외부에서는 nginx(80/443)로만 접속할 수 있습니다. 앱(8000)과 guacd(4822)는 서버 내부(127.0.0.1)에서만 열려 있습니다.
- 모든 API는 로그인해야 쓸 수 있고, 다른 엔지니어의 데이터에는 접근할 수 없습니다(403).
- 비밀번호는 PBKDF2로 저장합니다. 사이트·테스트서버 접속 비밀번호와 카드 번호는 `secret.key`로 암호화합니다.
- nginx 보안 헤더: `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`. HSTS는 자체 서명 인증서 경고를 넘길 수 없게 되므로 넣지 않았습니다.
- 원격 접속 대상으로 루프백, 컨테이너 내부망, 링크 로컬, 멀티캐스트 주소는 등록할 수 없습니다.

## 문제가 생겼을 때

| 증상 | 확인할 것 |
|---|---|
| 접속이 안 됨 (502) | `systemctl status se-portal`이 실행 중인지, `journalctl -u se-portal -n 50`에 오류가 있는지 |
| 로그인이 안 됨 | 승인 대기나 사용 중지 상태인지(계정 관리), 5회 실패로 잠겼는지(5분 뒤 다시 시도, 재시작하면 바로 풀림) |
| RDP가 연결되지 않음 | `systemctl status guacd`, `ss -ltn \| grep 4822` |
| SSH/RDP가 곧바로 끊김 | 30분 무입력 또는 포털 로그아웃에 의한 정상 종료인지. 사내 테스트서버 화면의 접속 기록에 사유가 남습니다. |
| 문서 다운로드 오류 | `data/doc_templates/`에 양식 파일이 있는지, 소유자가 `appuser`인지 |
| 구글 캘린더가 안 들어옴 | 구글 캘린더 연동 화면의 오류 표시, iCal 비공개 주소가 바뀌지 않았는지 |
| EOS 현황 갱신 실패 | 화면에 제품별 오류가 표시됩니다. 실패해도 이전 값은 유지되며, 1시간 뒤 다시 시도합니다. 서버에서 외부 HTTPS로 나갈 수 있는지 확인하세요. |
| 디스크 부족 | `df -h /`, `du -sh /opt/se-portal/uploads /opt/se-portal/data` |
